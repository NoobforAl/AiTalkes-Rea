Today we take one target apart twice: once by hand, once with an agent.

Target: a C program with weak cryptography

Inputsecret.txt
→
weak_encryptXOR with key, then +7
→
Outputsecret.enc
  • We only have the binary; we want to find the algorithm and the key
  • First we read the source code, then we look at the disassembly
  • It takes no arguments: the file names are hard-coded

Sample: sample/weakcrypt.c

Source 1: what does the program do with files?

#define IN_FILE "secret.txt"#define OUT_FILE "secret.enc" int main(void) { FILE *in = fopen(IN_FILE, "rb"); unsigned char buf[4096]; size_t n = fread(buf, 1, sizeof buf, in); weak_encrypt(buf, n); FILE *out = fopen(OUT_FILE, "wb"); fwrite(buf, 1, n, out); ...}
  • No arguments: fixed file names
  • Opens secret.txt in binary mode
  • Reads up to 4096 bytes into a buffer
  • Encrypts the buffer in place
  • Writes the result to secret.enc

Source 2: the weak encryption

static const char KEY[] = "S3cr3t!"; static void weak_encrypt(unsigned char *buf, size_t len) { size_t klen = strlen(KEY); for (size_t i = 0; i < len; i++) { buf[i] = (unsigned char)((buf[i] ^ KEY[i % klen]) + 7); }}
  • The key is constant and stays inside the binary
  • Key length: 7 bytes
  • A loop over every byte
  • XOR with a repeating key, then +7
Why weak? The key is short, fixed and repeating; both operations are reversible.

0x14000113e mov qword [var_10h], 70x140001147 mov qword [var_8h], 00x140001155 cmp rax, qword [var_20h]0x140001166 movzx eax, byte [rax+rcx]0x140001177 div qword [var_10h]0x140001180 lea rcx, str.S3cr3t_0x14000118b xor eax, ecx0x14000118d add eax, 70x14000119c mov byte [rax+rcx], dl
  • Select the key byte: i % 7
  • Load the constant key S3cr3t!
  • Combine byte and key: XOR
  • Then add 7. That's all!

Step 4: the control-flow graph (VV in radare2)

Reading the graph

  • Entry: locals are set up, key length 7, i = 0
  • Loop head: cmp + jae test i < len
  • Loop body: i % 7, load the key byte, xor, add 7, store, i++
  • Exit: return to main

Text version: agf

Sample 2: a hard target (vault)

Stripped + static

583 functions; most are libc and have no symbols.

Hidden key

The key is never a string; it is decoded at runtime.

Custom cipher

FNV-1a → xorshift64*
→ rotate + add

Decoys: fake AES-256 and S-box; anti-debug corrupts the key under a debugger.
